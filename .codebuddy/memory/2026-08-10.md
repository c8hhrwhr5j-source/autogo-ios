## 修复 CI 编译错误 — ScriptEngine ↔ TouchController API 不匹配 + Unmanaged<CFTypeRef> 类型错误

### 问题
GitHub Actions CI 编译失败，共 17 个错误：

**ScriptEngine.swift:**
- `l_tap/l_longPress/l_swipe`: 传参类型 `lua_Number`(Double) 未转为 `Int`
- `l_swipe`: `steps` 参数不存在于 TouchController.swipe()
- `l_touchDown/l_touchUp/l_touchMove`: TouchController 无此三个方法
- `l_multiTap`: `[(Double,Double)]` vs `[(x:Int,y:Int)]` 类型不匹配，`delayMs` 参数多余
- `l_pinch`: 参数签名完全不匹配，实际签名是 `pinch(centerX:centerY:scale:durationMs:)`

**TouchController.swift:**
- `AutoLuaHIDEventSystemClientCreate()` 返回 `Unmanaged<CFTypeRef>!`，需 `.takeRetainedValue()`
- `AutoLuaCreateDigitizerEvent()` 同样返回 `Unmanaged`，需解包
- `hidClient` 字段从 `let` 改为 `lazy var` 避免 init 时调用

### 修复
1. **TouchController.swift** — hidClient 加 `.takeRetainedValue()` 并改为 lazy var；postTouch 中 event 加 `?.takeRetainedValue()`；新增 touchDown/touchUp/touchMove 方法

## 修复脚本无法停止 + 无限循环阻塞队列

### 问题
用户反馈：脚本开始运行后没有下文，`print` 输出不显示，再次运行脚本无响应。

根因：
1. `main.lua` 使用 `while true do ... end` 无限循环，脚本的 `autolua.sleep()` 只阻塞串行队列 `queue` 的线程，但整个 Lua 运行被 `queue.sync` 阻塞，不会返回。
2. 点击“停止”后，`ScriptsViewController.stopScript()` **没有**调用 `ScriptEngine.shared.stop()`，仅设置 UI 状态。脚本仍运行在 `queue` 上，队列永久阻塞。
3. 后续点击“运行”时，`ScriptEngine.runLua` 的新 `queue.sync` 永远排队等待，导致新脚本永远无法执行。日志只有 `开始执行脚本` 没有 `脚本执行完成`。

### 修复
1. **BridgeImplementation.m** — 新增 `AutoLuaSetHookStop()` 和 Lua 调试钩子 `_autolua_stop_hook`，通过 `lua_sethook(L, hook, LUA_MASKLINE, 0)` 在每行代码执行时检查 `_autolua_should_stop` 标志，为真时调用 `luaL_error("Script stopped by user")` 抛出错误并中断脚本。
2. **BridgeHeader.h** — 声明 `AutoLuaSetHookStop()` 函数。
3. **ScriptEngine.swift** — 新增 `private var shouldStop: Bool` 和 `stop()` 方法；`stop()` 设置 `shouldStop=true` 并调用 `AutoLuaSetHookStop(L, 1)` 激活钩子；`runLua` 开头重置 `shouldStop=false` 并禁用钩子。
4. **ScriptsViewController.swift** — `stopScript()` 中添加 `ScriptEngine.shared.stop()` 真正中断 Lua 运行。

### 设计注意事项
- `lua_sethook` 从主线程调用修改 `lua_State` 是调试器常用模式，此处简单设置 flag + hook 函数指针，风险可控。
- 钩子在 `LUA_MASKLINE` 级别触发，即每行 Lua 代码执行一次检查。如果当前正在执行 C 函数（如 `autolua.sleep()`），钩子不会触发，需等待 C 函数返回后下一行才会中断。这属于可接受的延迟。

## 修复 getScreenSize 返回 0x0（截图权限不足时）

### 问题
`autolua.getScreenSize()` 返回 `0x0`。日志显示 `[ScreenCapture] 无法获取屏幕 Surface（可能缺少权限）`，说明 `startStreaming` 时 `AutoLuaGetMainDisplaySurface()` 返回 nil，`captureRawFrame()` 从未执行，`_cachedWidth/_cachedHeight` 保持默认值 0。

### 修复
`ScreenCapture.width/height` 从依赖缓存改为直接从 `UIScreen.main.bounds` 获取，乘以 `UIScreen.main.scale` 得到物理像素尺寸。这样即使截图权限不足，也能正确返回屏幕分辨率。

## 修复截图完全失效（IOMobileFramebuffer 私有 API 不可用）

### 问题
`autolua.findColor` 永远找不到颜色。日志显示 `[ScreenCapture] 无法获取屏幕 Surface`，`AutoLuaGetMainDisplaySurface()` 在 iOS 15.8.6 上因沙箱/权限限制返回 nil。`startStreaming` 直接 return，timer 不创建，`captureRawFrame()` 永不执行，所有找色/取色功能全部失效。

### 修复
1. **`startStreaming`** — 不再因私有 API 失败而直接返回，改为尝试获取 surface，失败时记录日志但仍继续启动 timer。
2. **`captureRawFrame`** — 添加方案2回退：当 `surface` 为 nil 或 `AutoLuaGetPixelData` 失败时，使用 `UIGraphicsImageRenderer` 截取当前窗口，再通过 `CGContext` 统一绘制到 BGRA 格式上下文中，保证与私有 API 的像素格式一致（`getPixelColor` 中 `pixels[offset+2]` 取 R、`+1` 取 G、`+0` 取 B）。
3. 回退方案在主线程执行 `DispatchQueue.main.sync`，因为 `UIGraphicsImageRenderer` 和 `drawHierarchy` 需要主线程。

## 修复 ScriptEngine 编译错误 — OpaquePointer 类型转换 + queue.sync 返回类型歧义

### 问题
1. `AutoLuaSetHookStop` 的 C 签名是 `void AutoLuaSetHookStop(void* L, int enable)`，Swift 端 bridged 为 `UnsafeMutableRawPointer?`，但传入了 `OpaquePointer` 类型，无法隐式转换。
2. `runLua` 的 `queue.sync { ... }` 闭包中第一行是 `shouldStop = false`（Void 语句），导致 Swift 类型推断将闭包返回类型推断为 `Void` 而非 `String`，与 `runLua() -> String` 签名冲突。

### 修复
1. `AutoLuaSetHookStop(L, n)` → `AutoLuaSetHookStop(UnsafeMutableRawPointer(L), n)` — 使用 `UnsafeMutableRawPointer` 的 `OpaquePointer` 构造器转换。
2. `runLua` 改用 `var result: String = ""` + `queue.sync { ... }`（无 return）+ `return result` 模式，避免闭包内 `return "..."` 与 Void 语句产生类型推断歧义。

## 三项改进：颜色调试输出 + main.lua 打包 + 后台常驻防闪退

### 1. main.lua 颜色不匹配时输出实际颜色
- `findColor` 结果先保存到变量 `c1/c2/c3`，再与期望值比较
- else 分支中输出所有坐标的实际颜色：`string.format("0x%06X", c1)` 和期望值
- 同时处理 `findColor` 返回 nil 的情况（输出"取色失败"）

### 2. main.lua 随 IPA 打包
- `project.yml` 中 `resources` 新增 `- path: main.lua`
- 构建时 main.lua 会被复制到 .app bundle 根目录
- `BackgroundScriptManager` 首次启动时自动从 Bundle 复制到 `/var/mobile/AutoLua/Scripts/main.lua`

### 3. 后台常驻运行（核心架构改进）
- **问题**：app 闪退或被 kill 后，Lua 脚本自动停止。脚本运行依赖 `ScriptsViewController` 的 `[weak self]` 回调，VC 销毁后脚本停止。
- **解决方案**：新建 `BackgroundScriptManager.swift`，脚本生命周期脱离 UI：
  - 单例模式，由 `AppDelegate.didFinishLaunching` 初始化
  - `applicationDidLaunch()` → 自动复制 bundled main.lua → 自动启动
  - `applicationDidEnterBackground()` → 开启 `UIBackgroundTaskIdentifier` 防止挂起
  - `startScript(name:path:)` 在专用 `runQueue` 上执行，不依赖任何 ViewController
  - `stopScript()` 设置 `autoRestart=false` 再中断 Lua VM
  - 脚本结束后若 `autoRestart==true`，自动重启（实现闪退恢复）
  - 状态变更通过 `NotificationCenter` 广播，UI 被动观察

- **ScriptsViewController 修改**：
  - 移除 `runQueue` 属性
  - `runScript` 改为调用 `BackgroundScriptManager.shared.startScript()`
  - `stopScript` 改为调用 `BackgroundScriptManager.shared.stopScript()`
  - 新增 `stateObserver` 监听 `BackgroundScriptManager.stateChangedNotification`，同步 `runningScriptURL`
  - 新增 `deinit` 清理 observer

- **AppDelegate 修改**：
  - `didFinishLaunching` 调用 `BackgroundScriptManager.shared.applicationDidLaunch()`
  - `applicationDidEnterBackground` 转发到 `BackgroundScriptManager`
  - `applicationWillEnterForeground` 转发到 `BackgroundScriptManager`

### 背景保活机制（三层保障）
1. **Silent Audio**（已有）：`AVAudioPlayer` 循环播放静音 WAV，利用 `audio` 后台模式
2. **UIBackgroundTaskIdentifier**（新增）：后台时申请系统后台任务，额外获得约 30s-180s 保护
3. **Auto-restart**（新增）：脚本异常退出后自动重拉，保证"任何时候不主动停止都在运行"
